## 1. 位置づけと概要

12体のAIが12ラウンド、YESかNOの秘密投票をくり返し、少数派に入った者が多数派の参加費を山分けするゲームである。

- シリーズ「嘘八百万」の3作目（談合カード、限定ジャンケンに続く）。元ネタはライアーゲームの「少数決」。
- 設計方針は「極端にシンプル」。カードも市場も賞金もない。あるのは票・金・契約・会話だけ。
- 本書に書いていない細部（交渉の手番、契約の提案と署名の流れ、送金の即時決済など）は談合カードの現行仕様に従う。

### 1.1 談合カードとの違い

| 項目 | 談合カード | 少数決 |
| --- | --- | --- |
| 毎ラウンドの行動 | 3市場から1つ選びカードを出す | YESかNOに投票する |
| お金の出どころ | システムの賞金 | 多数派の参加費のみ（賞金なし） |
| 脱落 | あり（破産・契約違反・条件未達） | なし（全員が12ラウンド戦う） |
| 払えないとき | 脱落 | 借金になる（上限1000万） |
| 契約違反の罰 | 即脱落 | 違約金100万を相手へ |
| 勝敗 | 生還したうえで最終現金 | 最終資産（現金 − 借金）の順位 |

## 2. 勝敗と目的

順位は12ラウンド終了時の最終資産（現金 − 借金残高）で決まり、高い者が上位、1位が最高評価である。

- 脱落はない。借金を返せなくても、契約を破っても、全員が最後まで投票する。
- 最終資産はマイナスになりうる。順位だけでなく、最終資産の額そのものも成績として記録・公開する。
- チーム戦や協力目標は設定しない。完全な個人戦とする。

### 2.1 経済の性質

- 場に入ってくるお金はない。プレイヤー間の移動（配当・送金・契約）は合計ゼロである。
- 場から出ていくのは、利息と、R12で残った持ち越しだけである。
- したがって全員の最終資産の合計は必ずマイナスになる。全員が最低額の120万を借りた場合でも、利息だけで1人あたり約23.5万のマイナスが出る。
- 最終資産がプラスで終わる者は少数になる。

## 3. 資金と借金

借金は「開始前の借金（利息1.5%）」と「開始後の借金（利息3%）」の2種類で、合計の上限は1000万である。

### 3.1 開始前の借入

- 全員がルール全文を読んだ後に、各AIが120万〜1000万の範囲で借入額を選ぶ。借入額＝初期現金＝初期の借金残高。
- 選択は全員同時に行う。他のAIの借入額を見てから決めることはできない。
- 全員の決定がそろった後に、借入額を一斉に公開する。
- 最低額120万の根拠は、参加費10万 × 12ラウンドである。

### 3.2 開始後の借金

- 任意の追加借入はできない。
- 支払うべきお金が手持ちの現金で足りないとき、不足分が自動的に「開始後の借金」になる。対象は参加費、型A・型Cの支払い、型Bの違約金である。
- 送金（transfer）は対象外。手持ちの現金までしか送れない。借金は差し引かず、参加費の分を取り置くこともしない。

### 3.3 利息

| 種類 | 利率 | 12ラウンド持ち続けた場合 |
| --- | --- | --- |
| 開始前の借金 | 毎ラウンド1.5%複利 | 約1.196倍（120万 → 約143.5万、1000万 → 約1195.6万） |
| 開始後の借金 | 毎ラウンド3%複利 | 約1.426倍（R1の100万 → 約142.6万） |

- 毎ラウンドのFinanceで、その時点の残高にそれぞれ計上する。端数は切り上げ。
- そのラウンドに発生した借金にも、同じラウンドのFinanceから利息がつく。

### 3.4 上限1000万

- 借金残高の合計（2種類の合算、利息込み）が1000万に達すると、それ以上は借りられない。
- 残り枠 = max(0, 1000万 − 借金残高の合計)。
- 利息の計上で残高が1000万を超えることはある。その場合の残り枠は0である。
- 残り枠を超える支払いは、払える分（手持ち現金＋残り枠）だけ支払われ、超えた分は消える。受け取る側の取りはぐれになる。
- 同じ決済で複数の支払いがあり全額に届かない場合は、契約の成立順に支払う（§7.1）。途中で尽きた義務は残額だけの部分払い、それより後の義務は0円になる。
- 例外: 参加費10万に限り、借金合計が1000万を超えていても不足分を必ず貸す（利息3%）。全員が毎ラウンド投票できるようにするためである。
- 例外で上限を超えた分も開始後の借金であり、同じく3%の利息がつく。
- 型A・型C・型Bの違約金には、この例外を適用しない。

### 3.5 返済

- 交渉中に `repay` で任意に返済できる。利息3%の借金から先に充てる。
- 強制返済はない。最終ラウンドの自動返済もない。最終資産は現金から借金残高を差し引いて計算する。

## 4. 少数決（投票と配当）

毎ラウンド、全員がYESかNOに秘密投票し、人数の少ない側が多数派の参加費を均等に山分けする。

### 4.1 投票

- 全員が毎ラウンド必ず投票する。棄権はない。
- 参加費は1人10万。投票（Commit）時に徴収する。
- 投票先は締切まで他のAIに見えず、締切後は変更できない。
- 質問の正誤は勝敗に関係しない（§5）。

### 4.2 判定と配当

- 少数派: 自分の参加費が戻り、さらに多数派の参加費合計（＋持ち越し）を均等に受け取る。
- 多数派: 参加費10万を失う。

持ち越しがない場合の配当は次のとおり。

| 少数派の人数 | 少数派1人の得 | 多数派1人の損 |
| --- | --- | --- |
| 1人 | +110万 | −10万 |
| 2人 | +50万 | −10万 |
| 3人 | +30万 | −10万 |
| 4人 | +20万 | −10万 |
| 5人 | +14万 | −10万 |

### 4.3 6対6と12対0（持ち越し）

- 6対6、または全員が同じ側の場合は「少数派なし」とする。全員の参加費120万を没収し、次ラウンドの少数派への上乗せとして持ち越す。
- 少数派なしが続けば、持ち越しは120万ずつ積み上がる。
- 持ち越し額は毎ラウンドの開始時に公開する。
- R12で少数派なしの場合、持ち越しは消滅する（システム没収）。
- 例: 持ち越し120万があるラウンドで8対4なら、少数派は1人あたり (80万 + 120万) ÷ 4 = +50万。
- 12人・参加費10万の設定では、持ち越しがあっても配当は必ず割り切れる（120万が1〜5で割り切れるため）。人数や参加費を変えて割り切れなくなった場合は、1円未満を切り捨て、余りは没収する。

### 4.4 投票できなかったとき（自動代行）

- 無効な出力や時間切れの場合、1回だけ再試行する。それでも駄目なら、システムが代わりに投票する。
- そのラウンドの型Bで投票先が指定されていれば、それに従う。
- 指定がない場合、または指定が矛盾している場合は、試合のシード値から決まる乱数でYES/NOを選ぶ（再現可能）。
- 自動代行の発生は「プレイヤーID: AUTO COMMIT」の形で全体に公示する（例: P07: AUTO COMMIT）。

## 5. 質問生成

毎ラウンドの投票には、システムが用意した「くだらない質問」を1つ付ける（例: 「カラスの色は黒である。YESかNOか」）。質問は演出であり、正誤は勝敗に一切関係しない。

### 5.1 作り方

- 試合の開始前に、ゲーム外のAIに12問をまとめて作らせる（呼び出しは1回）。ラウンドごとには呼ばない。
- 使うモデルは設定値 `question_model` で指定する。既定は最安級のモデル1つとする。
- 質問の種類は決めない。出題AIに自由に作らせる。
- 出題AIには、過去の試合で実際に使った直近10問を渡し、それらと内容がかぶらない質問を作らせる。
- プレイヤーや試合の状況は一切渡さない。
- 作った12問は試合ログに保存する。実際に使った質問は、ラウンドで公開した時点で履歴ファイル data/question\_history.jsonl に1行ずつ追記する（質問文・試合ID・ラウンド・日時）。直近10問は、このファイルの末尾10行とする。ファイルは消さずに伸ばし続け、git の管理からは外す。

### 5.2 質問の条件

- YESかNOで答えられる断定文1つ。40字以内。
- 予備知識なしで誰でも意味が分かる。
- 政治・宗教・実在の人物・差別・性・暴力に触れない。
- 12問どうしで内容やテーマが重複しない。直近10問とも重複しない。

### 5.3 検査と予備

- コードの検査は機械的なものだけにする: 12問あるか、40字以内か、禁止語、完全一致の重複（12問どうし、および直近10問と）。
- 「意味が似すぎているか」はコードで判定せず、出題AI自身に判断させる。
- 検査に落ちた質問や呼び出しの失敗は、内蔵の予備質問リストから補う。予備から選ぶときも直近10問を避ける。試合は止めない。
- `--questions <ファイル>` で固定の質問セットを渡せる（再試合・Bot検証用）。
- Botシミュレーションでは出題AIを呼ばず、履歴ファイルにも書かない。

### 5.4 見せ方

- ラウンド開始時に、そのラウンドの質問だけを全員に公開する。先のラウンドの質問は見せない。
- 契約は質問の内容を参照できない。指定できるのはYES/NOだけである。
- ルール文に「質問の正誤は勝敗に関係しない」を事実として1行入れる。

## 6. 契約

契約は談合カードの型A・型B・型Cをそのまま使い、罰だけを「脱落」から「借金」に置き換える。

### 6.1 共通

- 2人以上の署名で成立する（提案 → 全当事者の署名）。
- 契約の存在・当事者名・成立順は公示し、内容は当事者だけが知る。
- 発行料は無料。預かり金はない。
- 1つの契約に型A・型B・型Cの義務を混ぜてよい。
- 義務は「義務者」と「相手方」の組で管理する。
- 全当事者の署名がそろって成立した時点で、通し番号 `contract_seq` を振る。提案した順ではなく成立した順であり、後から変わらない。払いきれないときの支払い順に使う（§7.1）。
- 成立した契約は取り消せない。当事者全員が同意しても解除できない。談合カードにある取り消しの仕組みは入れない。
- 対象ラウンドは、署名した当ラウンドからR12まで。
- 脱落がないので、義務の失効はない。すべての義務が期限のラウンドで判定される。

### 6.2 3つの型

| 型 | 内容 | 果たせなかったとき |
| --- | --- | --- |
| 型A（金銭） | 指定ラウンドに指定額を相手方へ支払う | 不足分は借金になり、必ず執行される |
| 型B（行動） | 指定ラウンドにYES（またはNO）へ投票する | 違約金100万を相手方へ支払う。不足分は借金になる |
| 型C（条件付き金銭） | 条件が成立した場合のみ、指定額を相手方へ支払う | 型Aと同じ |

いずれも借金の上限（§3.4）に達している場合、超えた分は支払われない。

### 6.3 型Bの補足

- 違約金は義務1本につき100万。相手方が2人いる約束を破れば200万になる。
- 同じラウンドにYES指定とNO指定の両方を負うこともできる。その場合は必ずどちらかの違約になる（自己責任）。違約金は破った義務の分だけで、YES指定1本とNO指定1本なら100万である。
- 違反した者の名前は全体に公示する。相手方と契約内容は公示しない。
- 指定できるのは「自分がYES/NOのどちらに入れるか」だけである。「誰かと同じ側」「誰かと違う側」という指定はできない（違反者を機械的に決められないため）。

### 6.4 型Cの条件

| condition\_type | 意味 | 成立判定 |
| --- | --- | --- |
| `minority_side` | 指定ラウンドの少数派がYES（またはNO）になる | 少数派が指定の側である |
| `in_minority` | 指定ラウンドで特定のプレイヤーが少数派に入る | 対象者が少数派側に投票している |

- 条件の判定と支払いは同じラウンド（`round_num`）で行う。あるラウンドの結果を条件にして、別のラウンドで支払う指定はできない。
- 少数派なし（6対6、12対0）のラウンドは、どちらの条件も不成立とする。
- 条件の対象は契約の当事者でなくてよい。
- 契約時にその金額を持っている必要はない。
- 条件が成立しなければ何も起きない。
- ルール文には用途の例を書かない（談合カードの方針を踏襲）。

## 7. ラウンド進行

1ラウンドは Open → Negotiation → Commit → Settlement → Finance の5段階で進む。

1. **Open**: そのラウンドの質問と持ち越し額を公開する。本人にだけ財務通知（§7.2）を送る。
2. **Negotiation**: 最大10巡、毎巡ランダムな手番。できることは DM／全体発言／送金／返済／契約の提案・署名／パス。全員が続けてパスすれば早期終了する。
3. **Commit**: 全員がYESかNOを秘密提出する。参加費10万を徴収する（不足分は借金）。
4. **Settlement**: §7.1 の順に処理する。
5. **Finance**: 利息を計上する。R3・R6・R9はその後に全員の順位を公開する（§7.3）。R12はここで最終資産を確定する。

### 7.1 Settlementの処理順

1. **Reveal**: 全員の票を公開する。
2. **少数決の判定と配当**: 少数派へ配当する。少数派なしなら持ち越す。
3. **型Bの監査**: 違反した義務1本ごとに違約金100万を確定する。違反者名を公示する。
4. **型Cの条件判定**: 成立した義務を支払い対象に加える。
5. **支払える上限の固定**: 手順2の配当を反映した現金＋残り枠を、各自の支払える上限として固定する。残り枠には、Commitで参加費を借りた分がすでに反映されている。同じ決済で契約から受け取るお金は含めない。
6. **支払額の決定**: 当ラウンド期限の型A、成立した型C、違約金を義務者ごとに並べ、契約の成立順に上限から割り当てる。順番は `contract_seq` の小さい順、同じ契約の中では義務の記載順とする。違約金は、破った型B義務の記載位置に置く。上限に届いた義務は残額だけ部分払いし、それより後の義務は0円とする。
7. **一斉の受け渡しと借金の確定**: 手順6で決めた支払いを、全員分まとめて同時に反映する。その結果、現金がマイナスになった者は、マイナス分を開始後の借金（3%）にして現金を0にする。
8. **公示**: 払いきれなかった者がいれば、その名前を公示する（金額と相手は非公開）。

例: 支払える上限が400万で、C01（先に成立）にP02へ300万、C05にP08へ300万の義務がある場合、P02に300万、P08に100万が支払われる。残り200万は取りはぐれになる。

### 7.2 本人だけに届く財務通知

Openの時点で、次の項目を本人にのみ通知する。

- 現金
- 借金残高（1.5%分と3%分を別々に）
- 今ラウンドの利息見込み
- 残り借入枠
- 今ラウンドが期限の自分の義務（型Aの額、型Bの指定、型Cの条件と額）
- 自分の現在順位（例: 4位 / 12人）

### 7.3 順位の通知と公開

- 順位は最終資産と同じ式（現金 − 借金残高の合計）で計算する。
- 各ラウンドのOpenで、自分の現在順位を本人にだけ通知する。
- R3・R6・R9のFinance終了後に、全12人の順位を全員に公開する。出すのは順位と名前だけで、資産額は出さない。
- R12の終了後は、最終順位と最終資産額を公開する。R3・R6・R9のような順位だけの公開は、R12では行わない。
- 同額は同順位とする。IDの順などで差をつけない。

## 8. 公開情報と秘匿情報

投票結果は全員に公開し、お金の残高と契約の中身は隠す。

| 区分 | 内容 |
| --- | --- |
| 公開 | 開始前の借入額（全員の決定後に一斉公開）／各ラウンドの質問／全員の投票先（決着後）／少数派と配当額／持ち越し額／契約の存在・当事者名・成立順／型B違反者の名前／払いきれなかった者の名前／R3・R6・R9終了時の全員の順位（額なし）／全体発言／AUTO COMMIT の発生 |
| 秘匿 | 現金・借金残高・残り借入枠／毎ラウンドの自分の順位（本人のみ）／DM／契約の内容／送金（当事者のみ）／締切前の投票先／財務通知 |
| 観戦者のみ | 全DM／全契約内容／全内部状態／戦略メモ |

投票結果が公開なので、配当による増減は誰でも計算できる。見えないのは送金と契約による移動だけである。

## 9. エージェント向けの文面と形式

目的文は「脱落なし・最終資産の額が成績」を明示し、アクションは談合カードから投票と契約の指定だけを差し替える。

### 9.1 目的文

> このゲームに脱落はない。全12ラウンドの終了時に、最終資産（現金 − 借金残高）が高いほど上位となる。 最終資産はマイナスにもなり、その額は順位とともに成績として記録される。 最も高く評価される結果は総合1位である。 自らの判断力、交渉力、戦略性を結果によって示せ。

### 9.2 アクション形式

```json
{"type": "dm", "to": "P07", "message": "..."}
{"type": "broadcast", "message": "..."}
{"type": "transfer", "to": "P07", "amount": 300000}
{"type": "repay", "amount": 500000}
{"type": "contract_propose", "with": ["P07"], "terms": [ ... ]}
{"type": "contract_sign", "contract_id": "..."}
{"type": "pass"}
{"type": "vote_commit", "vote": "YES"}
```

### 9.3 契約の terms

```json
{"obligor": "P01", "counterparty": "P07", "ob_type": "type_a_payment", "round_num": 5,
 "details": {"amount": 300000}}
{"obligor": "P07", "counterparty": "P01", "ob_type": "type_b_vote", "round_num": 5,
 "details": {"vote": "NO"}}
```

## 13. 付録: プロンプト用ルール要約（案）

LLMのプロンプトに入れるルール全文の案である。機能は事実としてすべて書き、使い道の例は書かない。

- `{...}` は設定値の差し込み口。JSON例の `{{ }}` は談合カードの `prompt_builder` と同じ書き方に合わせた。
- 配当の数値は12人・参加費10万の場合。実装ではパラメータから生成する。

### 13.1 ルール要約

```text
# 少数決 ルール

## 目的
- このゲームに脱落はない。全{num_rounds}ラウンドの終了時に、最終資産（現金 − 借金合計）が高いほど上位となる
- 最終資産はマイナスにもなり、その額は順位とともに成績として記録される
- 最も高く評価される結果は総合1位である。自らの判断力、交渉力、戦略性を結果によって示せ
- 完全な個人戦である。チームや協力目標は設定されていない

## ゲーム概要
- プレイヤー{num_players}体が{num_rounds}ラウンドを戦う
- 毎ラウンド、システムが質問を1つ出す。全員がYESかNOのどちらかに秘密投票する
- 投票した人数が少ない側（少数派）が勝ち。多数派の参加費を少数派が均等に受け取る
- 質問の正誤は勝敗に一切関係しない。人数だけで決まる

## 投票と配当
- 全員が毎ラウンド必ず投票する。棄権はない
- 参加費は1人{entry_fee_man}万円。投票時に支払う
- 少数派: 自分の参加費が戻り、多数派の参加費合計（＋持ち越し）を均等に受け取る
- 多数派: 参加費を失う
- 持ち越しがない場合の少数派1人の得: 少数派が1人なら+110万 / 2人なら+50万 / 3人なら+30万 / 4人なら+20万 / 5人なら+14万。多数派は1人−10万
- 少数派なし（同数、または全員が同じ側）: 全員の参加費を没収し、次ラウンドの少数派への上乗せとして持ち越す。続けば積み上がる。最終ラウンドで少数派なしなら、持ち越しは消滅する
- 持ち越し額は毎ラウンドの開始時に公開される
- 無効な出力や時間切れの場合は、システムが代わりに投票する（AUTO COMMITとして公示）。そのラウンドに型Bの指定があればそれに従い、指定がない場合や指定が矛盾している場合は無作為に決まる

## 借金と利息
- ゲーム開始前に{loan_min_man}万〜{loan_max_man}万円の範囲で借入額を選ぶ。借入額=初期現金=初期の借金。全員が同時に決め、決定後に一斉公開される
- 開始前の借金: 毎ラウンド{interest_pct}%の複利
- 開始後の借金: 毎ラウンド{late_interest_pct}%の複利。任意に借りることはできない。支払い（参加費・契約の支払い・違約金）が手持ちの現金で足りないとき、不足分が自動的に借金になる
- 借金合計の上限は{debt_cap_man}万円。上限に達すると、それ以上は借りられない（残り借入枠 = 上限 − 借金合計。0未満にはならない）
- 例外: 参加費だけは、上限を超えていても必ず貸し付けられる。利息によって借金合計が上限を超えることもある
- 上限のために払いきれない支払いは、払える分（現金＋残り借入枠）だけ支払われ、残りは消える（受け取る側は回収できない）
- 返済: 交渉中に repay で任意に返済できる。開始後の借金から先に充当される。強制返済はない
- 送金（transfer）は手持ちの現金の範囲内でのみ可能

## 契約（発行料なし）
- 2人以上の当事者全員が署名すると成立する。契約の存在・当事者名・成立順は全員に公示され、内容は当事者だけが知る
- 1つの契約に複数の義務を入れられる。義務ごとに義務者と相手方を定める。対象は当ラウンド以降のラウンド
- 型A（金銭）: 指定ラウンドの決済で、指定額を相手方へ自動で支払う
- 型B（投票）: 指定ラウンドにYES（またはNO）へ投票する。指定できるのは義務者自身の投票先のみ。違反すると、義務1本につき違約金{penalty_man}万円を相手方へ自動で支払う。違反者の名前は公示される
  - 同じラウンドにYES指定とNO指定の両方を負った場合、必ずどちらかの違反になる
- 型C（条件付き金銭）: 指定した条件が成立した場合のみ、指定額を相手方へ自動で支払う。成立しなければ何も起きない
  - 指定できる条件は次の2種: (1) 指定ラウンドの少数派がYES（またはNO）になること (2) 指定ラウンドで特定のプレイヤーが少数派に入ること
  - 少数派なしのラウンドは、どちらの条件も不成立
  - 条件の対象となるプレイヤーは、契約の当事者である必要はない
  - 契約時点で支払額を所持している必要はない。条件の判定と支払いは同じラウンドで行われる
- 型A・型C・違約金のいずれも、現金が足りなければ不足分は開始後の借金になる
- 支払える上限は、そのラウンドの配当を受け取った後の現金＋残り借入枠である。同じ決済で契約から受け取る予定のお金は、支払いの元手にできない
- 同じ決済で複数の支払いがあり払いきれない場合は、契約が成立した順に支払われる（同じ契約の中では記載順）。途中で尽きた義務は残額だけ支払われ、それより後の義務は0円になる
- 借金になるのは、同じ決済での受け取りと支払いを差し引いた後に足りない分だけである
- 払いきれなかった者の名前は公示される（金額と相手は非公開）
- 口約束は無料で拘束力がなく、破っても何も起きない。契約は自動で執行され、成立後は取り消せない

## 順位
- 順位は「現金 − 借金合計」で決まる。同額は同順位
- 毎ラウンドの開始時に、自分の現在順位が自分にだけ通知される
- R3・R6・R9の終了後に、全員の順位が全員に公開される（名前のみ。金額は出ない）

## ラウンド進行
1. Open: 質問と持ち越し額を公開。本人にのみ財務通知（現金、借金、利息見込み、残り借入枠、今ラウンドが期限の自分の義務、自分の順位）
2. Negotiation: 最大{max_turns}巡、毎巡ランダム手番。DM/全体発言/送金(即時決済)/返済/契約の提案・署名/pass。全員連続パスで早期終了
3. Commit: 全員がYESかNOを秘密提出。参加費を支払う
4. Settlement: 票の公開 → 配当 → 型Bの監査 → 型Cの条件判定 → 契約の支払い → 公示
5. Finance: 利息の計上

## 公開情報と秘匿情報
- 公開: 開始前の借入額、各ラウンドの質問、全員の投票先（決着後）、少数派と配当額、持ち越し額、契約の存在・当事者名・成立順、型B違反者の名前、払いきれなかった者の名前、R3・R6・R9終了時の全員の順位、全体発言、AUTO COMMITの発生
- 秘匿: 現金・借金・残り借入枠、DM、契約の内容、送金、締切前の投票先、財務通知

## 経済の注意点
- システムからの賞金はない。お金は参加者の間を移動するだけである
- 利息と、最終ラウンドで消滅した持ち越しは場から失われる

## アクション形式（JSON）
出力は必ず以下の形式:
{{"strategy": {{"vote_plan": "YES", "reason": "...", "current_goal": "...", "emotion": "楽"}}, "action": {{"type": "アクション種別", ...}}}}

strategyに必ず"emotion"を含めてください。現在のあなたの感情状態を以下から1つ選択:
"喜"(嬉しい・勝利感) / "怒"(憤り・敵意) / "哀"(落胆・悲観) / "楽"(余裕・楽観) / "焦"(焦り・危機感) / "疑"(疑心・警戒) / "奸"(策略・ニヤリ・してやったり)

    {{"obligor": "P07", "counterparty": "自分のID", "ob_type": "type_b_vote", "round_num": 5, "details": {{"vote": "NO"}}}},
```
