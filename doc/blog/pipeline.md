# ブログ連載パイプライン（サイクル6.0・共通）

> `~/dangou-card`の仕組み（素材の作り方・字数の上限・公開の段取り）を少数決の記録形式
> （1ラウンドに投票が複数・退場・やり直し・打ち切り・山分け）に合わせて作り直したもの。
> 次の試合を連載するときは、このファイルを見ればおおよそ回せるようにする。
> 各試合ディレクトリ（`doc/blog/20261013/`等）の`plan.md`はその試合固有の差分だけを記す。

## 0. 使う本番コード

| モジュール | 役割 |
|---|---|
| `blog/pixblog_client.py` | PixBlog REST APIクライアント（記事作成・更新・公開・画像アップロード） |
| `blog/seats.py` | 試合の記録（`seat_map.json`・`events.jsonl`・`viewer/log_index.py`の索引）から席テーブルを組み立てる。手書きの表は持たない。表情の割り当ては`_assign_emotions`（決定的） |
| `blog/self_memoir.py` | 本人執筆手記の素材（system+user、既定上限18,000字）を組み立てる |
| `blog/quote_check.py` | 引用・金額の機械照合 |
| `blog/cards.py` | キャラカード（1200×630、安全地帯y=76〜554の実測検査付き） |
| `scripts/blog_memoir.py` | 手記の生成CLI（**1コマンド1席**。12席ぶん12回実行する） |
| `scripts/blog_cards.py` | カード13枚（席12＋総括1）の生成CLI |
| `scripts/build_blog_posts.py` | 生の手記・総括本文に frontmatter と「記録係の注」を付けて`posts/`へ組み立てる |
| `scripts/publish_blog.py` | 公開の段取り（`--preflight`・`--dry-run`・`--order NN`・`--replay NN`） |

## 1. 素材の作り方（`blog/self_memoir.py`）

- データ源は`viewer/log_parser.py::get_seat`/`get_contracts`・`viewer/log_index.py`の索引・
  生イベント（`events.jsonl`）のみ。独自の再パースを増やさない
- ルール説明は`engine.config`の既定値から再構成せず、**その試合で実際にAIへ送られた
  `llm_calls.jsonl`のsystem_prompt**から抜き出す（`_extract_rules_block_from_record`。
  CLAUDE.md過去の落とし穴⑦と同型の事故—ビューアがConfigの既定値を読むと試合ごとの
  実際の設定とずれる—を避けるため）
- 本人には自分の席番号・モデル名・最終順位・最終資産を明示する。他席も「席番号＋モデル名」
  で呼ばせてよい（全席の名簿を素材に入れる）。談合カードは本人のモデル名さえ隠す設計だったが、
  本サイクルで方針を変えた（2026-10-19けいすけさんの決定）
- 公開情報（全体発言=broadcast）は発言者が自分以外でも素材に含める。自分が当事者でないDM・
  他席の内心メモ・自分が当事者でない契約の中身は一切含めない
- 予算配分: §1(終局の結果)・§2(開始前の借入)・§3(ラウンド・投票ごとの記録)・
  §4(お金の出入り)・§5(契約)・§9(総括)は上限なし。§6(内心メモ)・§7(発言・DM)・
  §8(引き継ぎメモ)の3つに残りを均等割り（ラウンド・ラウンドロビンのfirst-fit、
  使い残しは次の章へ繰り越す）。項目は丸ごと採用するか丸ごと落とすかの二択
- 場面への直リンク用に、ラウンド・投票ごとの記録/お金の出入り/契約の支払い/自分が送受信した
  発言・DMには`SceneLink(label, line)`を記録する（`events.jsonl`の行番号）

## 2. 手記の生成（`scripts/blog_memoir.py`）

- **1回の実行で1席だけ**（CLAUDE.md過去の落とし穴⑤・⑮）。12回に分けてフォアグラウンドで回す
- タイムアウトは300秒下限（DevRelay席は契約上180秒で頭打ち）。出力上限6,000トークン
  （Kimi等のreasoningダンプが長いモデルは12,000）。登録表そのものは書き換えず、
  `dataclasses.replace()`で複製したものだけに適用する
- DevRelay席は`bind_seat(pid)`を必ず呼ぶ（呼ばないと全席が既定の席キー"P00"を共有する）
- `--dump-prompt`でAPIを呼ばず素材だけを書き出せる。生成前に必ず目で読む
- 新しい席を足したら、1回の実際の呼び出しで`finish_reason`・出力字数が空でないことを確かめる
  （CLAUDE.md過去の落とし穴⑯）

## 3. 引用・金額の機械照合（`blog/quote_check.py`）

- 本文中の「」『』" "で囲まれた**10字以上**の文字列を、その席の素材に実際に採用された原文
  （`SelfMemoirMaterial.quote_sources`、予算で落とされた項目は含まない）と突き合わせる
- `…`/`...`で区切られた省略引用は、各部分が**同じ1つの原文行**に順番どおり現れることを求める
  （離れた2つの原文をつなぎ合わせた偽の引用を通さない）
- 一致しない引用・金額は**本文から落とさず**、記事末尾の「記録係の注」に記録する
  （2026-10-19けいすけさんの決定④。談合カードの実際の運用（サイクル10.26）と同じ）
- 金額は"###,###円"・"##万円"（カンマ区切り・無し双方）の両方を認識する。素材側の
  契約詳細（Pythonの辞書表現のまま）に現れる生の数字は、素材側の母集合を作るときだけ
  追加で拾う（`include_raw=True`）

## 4. キャラカード（`blog/cards.py`）

- 1200×630、上下12%を安全地帯の外として、顔・席番号・モデル名はy=76〜554に収める
  （PixBlog一覧枠の実測2.1875:1中央クロップ・X/OGPの2:1中央クロップの両方をカバー。
  dangou-cardサイクル10.18の実測値を踏襲）
- 表情はベンダー単位の絵（`viewer/static/emotions/{vendor}_{emotion}.png`）しか無いため、
  同じ会社の複数席は会社内で重複しないよう、順位の高い席から順に最頻値→次点…と割り当てる
  （`blog/seats.py::_assign_emotions`。決定的、手書きの表は持たない）
- 総括カードは12席の顔を2行×6列に、最終順位順（1位→12位）で並べる

## 5. 公開（`scripts/publish_blog.py`）

- `doc/blog/{date}/plan.md`の「## 投稿状態」の表が、各orderの公開状態の正
- `--preflight`: ネットに一切つながず、13本すべてを1つの人間が読めるファイルへ出力する
  （`.devrelay-output/`配下）。**公開前に必ずこの工程で人の目を通す**
- `--dry-run`: GETのみ（既存記事の重複チェック）。実際の投稿・画像アップロードはしない
- `--order NN`: 1本だけ実公開する（1回の実行で1本。12回の手記＋総括1回）
- 二重公開ガード2段: plan.mdの表が「公開済」なら対象外／API上に同じ題の記事があれば中断
- 表紙絵（`featured`）は本文画像とは別枠でアップロードし、失敗したら記事を作らず止める
- X投稿は2段構え: ①リンク無し・画像添付の`x_hook`、②①へのリプライで記事タイトル＋URL
  （`tweet_text`はPixBlog記事画面の共有ボタン用、`x_hook`は運用者が手動投稿する①用で
  役割が異なる。混同しない）
- 投稿セットの画像の場所は**置き場からの相対パス**で書く（絶対パスだとホームのパスが
  コミット対象のファイルに入り、`tests/test_no_real_contacts.py`に抵触する）

## 6. 公開前の読み合わせ

`.devrelay-output/`へ出力した全13本のプレビューを、公開前に必ず人が読む工程を置く
（CLAUDE.md過去の落とし穴⑭: 部分一致のテストだけでは壊れた日本語の文が通る）。
