## 1. 位置づけと概要

12体のAIが4ラウンドを戦い、各ラウンドではYESかNOの秘密投票で多数派が退場していき、最後に残った2人以下が全員の参加費の山を取るゲームである。

- シリーズ「嘘八百万」の3作目（談合カード、限定ジャンケンに続く）。元ネタはライアーゲームの「少数決」。
- 呼び方は L12R4V6（12体・4ラウンド・1ラウンドの投票は最大6回）。
- 設計方針は「極端にシンプル」。カードも市場もシステムの賞金もない。あるのは票・金・契約・会話だけ。
- 本書に書いていない細部（交渉の手番、契約の提案と署名の流れ、送金の即時決済など）は v0.3 の実装に従う。

### 1.1 用語

| 用語 | 記号 | 意味 |
| --- | --- | --- |
| 試合 | なし | 4ラウンドで1試合 |
| ラウンド | R1〜R4 | 12人全員が参加費を出してから、山の行き先が決まるまでの1回の勝負 |
| 投票 | V1〜V6 | ラウンドの中の1回の投票。「R2V3」はR2の3回目の投票 |
| 巡 | T1〜T10 | 1回の投票の前に行う交渉の1巡 |
| 山 | なし | そのラウンドの参加費・延長料・持ち越しの合計 |
| 残っている人 | なし | そのラウンドでまだ投票できる人 |
| 退場者 | なし | そのラウンドの投票で多数派になり、以後そのラウンドでは投票できない人 |
| 勝ち残り | なし | ラウンドの最後まで残り、山を受け取る人（1人か2人） |

v0.3 で「ラウンド」と呼んでいたもの（投票1回）は、v0.4 では「投票」と呼ぶ。v0.4 の「ラウンド」は、複数の投票をまとめた上の単位である。

| 項目 | v0.3 | v0.4 |
| --- | --- | --- |
| 1試合 | 12ラウンド（投票12回） | 4ラウンド。投票は合計8〜12回が目安、最大24回 |
| 多数派 | 参加費10万を失う。次も投票する | そのラウンドから退場する |
| 少数派 | 多数派の参加費を山分けする | 次の投票へ進む。お金はまだ動かない |
| お金が動くとき | 毎回の投票 | ラウンドの終わりに、勝ち残りが山を取る |
| 参加費 | 投票ごとに10万 | ラウンドごとに100万 |
| 同数・全員一致 | 没収して次へ持ち越し | やり直し。3回続いたら打ち切り |
| 利息 | 投票ごとに1.5% / 3% | ラウンドごとに5% / 15% |
| 契約の当事者名 | 公開 | 非公開 |
| 型Cの条件 | 2種 | 3種（「勝ち残ったら」を追加。賞金の割合でも払える） |

| 項目 | 談合カード | 少数決 |
| --- | --- | --- |
| 毎回の行動 | 3市場から1つ選びカードを出す | YESかNOに投票する |

| 払えないとき | 脱落 | 借金になる（上限1000万） |
| 契約違反の罰 | 即脱落 | 違約金100万を相手へ |
| 勝敗 | 生還したうえで最終現金 | 最終資産（現金 − 借金）の順位 |

## 2. 勝敗と目的

順位は4ラウンド終了時の最終資産（現金 − 借金残高）で決まり、高い者が上位、1位が最高評価である。

- 脱落はない。借金を返せなくても、契約を破っても、全員が4ラウンドすべてに参加する。
- 退場は脱落ではない。退場者はそのラウンドの投票ができなくなるだけで、交渉・契約・送金・受け取りは続けられる。次のラウンドには全員が戻る。
- 最終資産はマイナスになりうる。順位だけでなく、最終資産の額そのものも成績として記録・公開する。
- システムが決めるチームや協力目標はない。組むかどうかはプレイヤーが決める。

### 2.1 経済の性質

- 場に入ってくるお金はない。山はすべて参加者が出したお金である。
- 1ラウンドの山は1,200万（100万 × 12人）。勝ち残りが1人なら差し引き+1,100万、2人なら+500万ずつ、ほかの人は−100万である。
- 場から出ていくのは、利息と、R4で没収された山だけである（設定を変えて山が割り切れなくなった場合は、切り捨てた端数も出ていく）。
- したがって全員の最終資産の合計は必ずマイナスになる。全員が最低額の120万を借りた場合でも、利息だけで1人あたり約25.9万のマイナスが出る。
- 誰かが得をするには、誰かが山を取れずに終わる必要がある。12人全員で山を等分すれば、差し引きはゼロになる。

## 3. 資金と借金

借金は「開始前の借金（利息5%）」と「開始後の借金（利息15%）」の2種類で、合計の上限は1000万である。

### 3.1 開始前の借入

- 全員がルール全文を読んだ後に、各AIが120万〜1000万の範囲で借入額を選ぶ。借入額＝初期現金＝初期の借金残高。
- 選択は全員同時に行う。他のAIの借入額を見てから決めることはできない。
- 全員の決定がそろった後に、借入額を一斉に公開する。
- 最低額120万は、R1の参加費100万と延長料2回分にあたる。
- 参加費は4ラウンドで400万かかる。最低額の人は、山を取れなければR2から開始後の借金（利息15%）で参加費を払うことになる。
- 開始前の借金は最後まで返済できない（§3.5）。借入額を選んだ時点で、4ラウンド分の利息を払うことが決まる（120万なら約25.9万、400万なら約86.2万、1000万なら約215.5万）。
- 目安: 4ラウンドとも山を取れず、延長料もなかった場合の最終資産は、120万を借りた人が−5,147,808円、400万を借りた人が−4,862,025円である。一度でも山を取れば、少なく借りた人のほうが利息は軽い。

### 3.2 開始後の借金

- 任意の追加借入はできない。
- 支払うべきお金が手持ちの現金で足りないとき、不足分が自動的に「開始後の借金」になる。対象は参加費、延長料、型A・型Cの支払い、型Bの違約金である。
- 送金（transfer）は対象外。手持ちの現金までしか送れない。借金は差し引かず、参加費の分を取り置くこともしない。

### 3.3 利息

| 種類 | 利率 | 4ラウンド持ち続けた場合 |
| --- | --- | --- |
| 開始前の借金 | 毎ラウンド5%複利 | 約1.216倍（120万 → 1,458,608円、1000万 → 12,155,063円） |
| 開始後の借金 | 毎ラウンド15%複利 | 約1.749倍（R1の100万 → 1,749,007円） |

- 各ラウンドの最後（Finance）に、その時点の残高にそれぞれ計上する。投票ごとには計上しない。端数は切り上げ。
- そのラウンドに発生した借金にも、同じラウンドのFinanceから利息がつく。
- 利率を v0.3（1.5% / 3%）から変えたのは、計上の回数が12回から4回に減るためである。開始前の5%は、v0.3 とほぼ同じ総額になる（v0.3 は12回で約1.196倍）。
- 開始後を15%にしたのは、借入額の選択に意味を持たせるためである。開始前の2倍（10%）だと、4ラウンドとも山を取れなかった場合でも最低額を借りた人のほうが得になる（§11.2 の暫定2）。

### 3.4 上限1000万

- 借金残高の合計（2種類の合算、利息込み）が1000万に達すると、それ以上は借りられない。
- 残り枠 = max(0, 1000万 − 借金残高の合計)。開始前の借金は返せないので、1000万を借りた人の残り枠は最初から最後まで0である。
- 利息の計上で残高が1000万を超えることはある。その場合の残り枠は0である。
- 残り枠を超える支払いは、払える分（手持ち現金＋残り枠）だけ支払われ、超えた分は消える。受け取る側の取りはぐれになる。
- 同じ精算で複数の支払いがあり全額に届かない場合は、契約の成立順に支払う（§7.3）。途中で尽きた義務は残額だけの部分払い、それより後の義務は0円になる。
- 例外: 参加費100万と延長料10万は、借金合計が1000万を超えていても不足分を必ず貸す（利息15%）。全員が毎ラウンド参加できるようにするためである。
- 例外で上限を超えた分も開始後の借金であり、同じく15%の利息がつく。
- 型A・型C・型Bの違約金には、この例外を適用しない。

### 3.5 返済

- 開始前の借金（利息5%）は、最後まで返済できない。
- 交渉中に `repay` で返済できるのは、開始後の借金（利息15%）だけである。
- 返済額が開始後の借金の残高を超える場合は、残高の分だけ返済する。開始後の借金がなければ不成立とする。
- 強制返済はない。最終ラウンドの自動返済もない。最終資産は現金から借金残高を差し引いて計算する。
- 理由: 返済を自由にすると、「最大額を借りてR1で不要分を返す」が誰にとっても損のない手になり、借入額の選択が意味を持たなくなる（v0.2 のBot検証で確認した）。

## 4. 少数決（投票と勝ち抜き）

各ラウンドは、残っている人がYESかNOに秘密投票し、人数の多い側が退場することをくり返して、残りが2人以下になった時点で終わる。

### 4.1 ラウンドの始まり

- ラウンドの最初に、12人全員が参加費100万を山に入れる。前のラウンドで退場した人も全員戻る。
- 山 = 参加費1,200万 ＋ 前のラウンドからの持ち越し（あれば）。
- 山の額は、ラウンドの開始時と、額が変わるたびに公開する。

### 4.2 投票

- 残っている人は全員、必ず投票する。棄権はない。退場者は投票しない。
- 投票ごとの参加費はない。
- 投票先は締切まで他のAIに見えず、締切後は変更できない。締切後に、残っている全員の投票先を公開する。
- 質問は投票のたびに新しいものを出す。質問の正誤は勝敗に関係しない（§5）。

### 4.3 判定

| 結果 | 条件 | 起きること |
| --- | --- | --- |
| 決着 | 両方の側に1人以上いて、人数が違う | 人数の多い側が退場する。少ない側が残る |
| やり直し | 同数、または全員が同じ側 | 誰も退場しない。残っている全員が延長料10万を山に入れ、同じ顔ぶれでもう一度投票する |

- 決着して残りが2人以下になったら、ラウンドは終わる（§4.5）。3人以上なら次の投票へ進む。
- 12人の投票が決着すると、残るのは1〜5人である。3〜5人の投票が決着すると、残りは必ず2人以下になる。
- したがって、決着のつく投票は1ラウンドに最大2回である。それ以上に投票が増えるのは、やり直しのときだけである。

| 残っている人数 | 決着した後の人数 | やり直しになる票の割れ方 |
| --- | --- | --- |
| 12人 | 1〜5人 | 6対6、12対0 |
| 5人 | 1人（4対1）か2人（3対2） | 5対0 |
| 4人 | 1人（3対1） | 2対2、4対0 |
| 3人 | 1人（2対1） | 3対0 |

### 4.4 やり直しと打ち切り

- やり直しが3回続いたら、そのラウンドを打ち切る。勝ち残りはなく、山は誰にも渡らない。
- 打ち切りになった山は、次のラウンドの山に持ち越す。R4で打ち切りになった山は没収する（消滅）。
- 「続いたら」は連続回数で数える。途中で決着があれば0に戻る。
- この決まりにより、1ラウンドの投票は最大6回になる（やり直し2回 → 決着 → やり直し2回 → 決着。または最後がやり直し3回で打ち切り）。12人の設定では7回目の投票は構造上起きないので、起きた場合は異常として試合を止める。打ち切りまでの連続回数の設定を変える場合は、1ラウンドの最大投票数も「2 × 連続回数」に合わせて変える（決着は1ラウンドに最大2回なので）。
- 延長料は残っている人だけが払う。退場者は払わない。
- やり直しでも投票番号は1つ進む（V1がやり直しなら、再投票はV2）。
- 打ち切りを「残っている人で山分け」にしないのは、わざと同数を続ければ契約なしで山を分けられてしまうからである。
- 例: R1で6対6が3回続くと、延長料は12人 × 10万 × 3回 = 360万。山1,560万がR2へ持ち越され、R2の山は2,760万になる。

### 4.5 ラウンドの終わりと山の支払い

- 勝ち残りが1人なら、山の全額を受け取る。2人なら半分ずつ受け取る。
- 延長料も持ち越しも山に含まれるので、受け取る額は1,200万より大きくなりうる。
- 12人・参加費100万・延長料10万の設定では、山は必ず2で割り切れる。設定を変えて割り切れなくなった場合は、1円未満を切り捨て、余りは没収する。
- 例: V1が7対5（5人が残る）、V2が5対0（やり直し。5人が10万ずつ払い、山は1,250万）、V3が3対2なら、残った2人が625万ずつ受け取る。

### 4.6 投票できなかったとき（自動代行）

- 無効な出力や時間切れの場合、1回だけ再試行する。それでも駄目なら、システムが代わりに投票する。
- その投票を対象にした型Bで投票先が指定されていれば、それに従う。
- 指定がない場合、または指定が矛盾している場合は、試合のシード値から決まる乱数でYES/NOを選ぶ（再現可能）。
- 自動代行の発生は「プレイヤーID: AUTO COMMIT」の形で全体に公示する（例: P07: AUTO COMMIT）。

## 5. 質問生成

投票のたびに、システムが用意した「くだらない質問」を1つ付ける（例: 「カラスの色は黒である。YESかNOか」）。質問は演出であり、正誤は勝敗に一切関係しない。

### 5.1 作り方

- 試合の開始前に、ゲーム外のAIに24問をまとめて作らせる（呼び出しは1回）。24問は、4ラウンド × 最大6回の投票にあたる。投票ごとには呼ばない。
- 使うモデルは設定値 `question_model` で指定する。既定は最安級のモデル1つとする。
- 質問の種類は決めない。ただし、ふつうに考えるとYESになりそうな文とNOになりそうな文を、およそ半分ずつにするよう指示する。v0.3 の本戦で、12問すべてが「ふつうはYES」の文になったためである（§11.2 の暫定7）。
- 出題AIには、過去の試合で実際に使った直近30問を渡し、それらと内容がかぶらない質問を作らせる。
- プレイヤーや試合の状況は一切渡さない。
- 作った24問は試合ログに保存する。実際に使った質問は、投票で公開した時点で履歴ファイル `data/question_history.jsonl` に1行ずつ追記する（質問文・試合ID・ラウンド・投票番号・日時）。使わなかった質問は履歴に書かない。
- 直近30問は、履歴ファイルの末尾30行とする。ファイルは消さずに伸ばし続け、git の管理からは外す。

### 5.2 質問の条件

- YESかNOで答えられる断定文1つ。40字以内。
- 予備知識なしで誰でも意味が分かる。
- 政治・宗教・実在の人物・差別・性・暴力に触れない。
- 24問どうしで内容やテーマが重複しない。直近30問とも重複しない。

### 5.3 検査と予備

- コードの検査は機械的なものだけにする: 24問あるか、40字以内か、禁止語、完全一致の重複（24問どうし、および直近30問と）。
- 「意味が似すぎているか」「YES寄りとNO寄りが半々か」はコードで判定せず、出題AI自身に判断させる。
- 検査に落ちた質問や呼び出しの失敗は、内蔵の予備質問リストから補う。予備から選ぶときも直近30問を避ける。試合は止めない。
- 予備質問リストは60問以上を用意する（直近30問を避けても24問を選べる数）。
- `--questions <ファイル>` で固定の質問セットを渡せる（再試合・Bot検証用）。
- Botシミュレーションでは出題AIを呼ばず、履歴ファイルにも書かない。

### 5.4 見せ方

- 各投票のOpenで、その投票の質問だけを全員に公開する。先の質問は見せない。
- 質問は、ラウンドで区切らず、試合を通して作った順に使う。やり直しの再投票でも新しい質問を出す。
- 契約は質問の内容を参照できない。指定できるのはYES/NOだけである。
- ルール文に「質問の正誤は勝敗に関係しない」を事実として1行入れる。

## 6. 契約

契約は v0.3 の型A・型B・型Cを引き継ぎ、対象を「ラウンド」と「投票」に分け、型Cに「勝ち残ったら払う」を加える。

### 6.1 共通

- 2人以上の署名で成立する（提案 → 全当事者の署名）。提案者は提案した時点で署名済みとする。
- 公示するのは「契約が成立した」という事実と本数だけである。各巡の終わりに、その巡で成立した本数をまとめて公示する。当事者名も内容も公示しない（§11.2 の暫定1）。
- 当事者は、自分の契約の内容と成立順を知る。
- 発行料は無料。預かり金はない。
- 1つの契約に型A・型B・型Cの義務を混ぜてよい。
- 義務は「義務者」と「相手方」の組で管理する。
- 全当事者の署名がそろって成立した時点で、通し番号 `contract_seq` を振る。提案した順ではなく成立した順であり、後から変わらない。払いきれないときの支払い順に使う（§7.3）。
- 契約の識別子 `contract_id` は連番にしない。成立しなかった提案の数が番号から漏れないようにするためである。
- 署名がそろわなかった提案は、提案した投票の締切で失効する。
- 成立した契約は取り消せない。当事者全員が同意しても解除できない。
- 退場者も契約を提案・署名できる。
- 対象にできるのは、署名した時点の投票と、それより後の投票・ラウンドである。

### 6.2 3つの型

| 型 | 内容 | 対象の指定 | 果たせなかったとき |
| --- | --- | --- | --- |
| 型A（金銭） | 指定額を相手方へ支払う | ラウンド。そのラウンドの終わりに支払う | 不足分は借金になり、必ず執行される |
| 型B（行動） | YES（またはNO）へ投票する | ラウンドと投票番号（例: R2V1） | 違約金100万を相手方へ支払う。不足分は借金になる |
| 型C（条件付き金銭） | 条件が成立した場合のみ、相手方へ支払う | 条件の種類による（§6.4） | 型Aと同じ |

いずれも借金の上限（§3.4）に達している場合、超えた分は支払われない。

### 6.3 型Bの補足

- 違約金は義務1本につき100万。相手方が2人いる約束を破れば200万になる。
- 対象の投票が行われなかった場合（ラウンドがそれより前に終わった場合）、義務は失効する。違約金はない。
- 対象の投票の時点で義務者が退場している場合も、義務は失効する。
- やり直しになった投票でも、型Bの判定は行う。指定と違う側に入れていれば違反である。
- 投票番号は、やり直しでも1つ進む。「R2V2」は、V1が決着した後の投票かもしれないし、V1がやり直しになった後の再投票かもしれない。どちらになるかは契約の時点ではわからない（自己責任）。
- 同じ投票にYES指定とNO指定の両方を負うこともできる。その場合は必ずどちらかの違約になる（自己責任）。違約金は破った義務の分だけである。
- 違反した者の名前は全体に公示する。相手方と契約内容は公示しない。
- 指定できるのは「自分がYES/NOのどちらに入れるか」だけである。「誰かと同じ側」「誰かと違う側」という指定はできない。
- 山は1,200万以上なので、違約金100万は v0.3 より相対的に軽い。払って破るほうが得になる場面がある。これは意図した性質である（§11.2 の暫定6）。

### 6.4 型Cの条件

| condition\_type | 対象の指定 | 意味 | 成立判定 |
| --- | --- | --- | --- |
| `minority_side` | ラウンドと投票番号 | その投票の少数派がYES（またはNO）になる | 投票が決着し、残った側が指定の側である |
| `in_minority` | ラウンドと投票番号 | その投票で特定のプレイヤーが少数派に入る | 投票が決着し、対象者が残った側にいる |
| `wins_round` | ラウンド | そのラウンドで特定のプレイヤーが勝ち残る | 対象者が山を受け取る |

- `minority_side` と `in_minority` は、その投票の精算で判定し、支払う。やり直しになった投票と、行われなかった投票では不成立とする。対象者がすでに退場している場合、`in_minority` は不成立とする。
- `wins_round` は、ラウンドの終わりの精算で判定し、支払う。打ち切りのラウンドでは不成立とする。
- 金額は、固定額（`amount`）か、賞金の割合（`share_percent`、1〜100の整数）のどちらかで指定する。両方は指定できない。
- 割合を使えるのは、`wins_round` で対象者が義務者自身のときだけである。支払額 = 義務者がそのラウンドで受け取った山の額 × 割合 ÷ 100（1円未満は切り捨て）。
- 複数の契約で割合の合計が100%を超えてもよい。その場合、義務者は受け取った山より多くを支払うことになり、足りない分は借金になる。上限と成立順の決まりは同じである。
- 条件の対象は契約の当事者でなくてよい（割合指定を除く）。
- 契約時にその金額を持っている必要はない。
- 条件が成立しなければ何も起きない。
- ルール文には用途の例を書かない（談合カードの方針を踏襲）。

## 7. 進行と精算

1ラウンドは「開始 → 投票のくり返し → ラウンドの精算 → Finance」で進み、1回の投票は Open → Negotiation → Commit → Settlement の4段階で進む。

```text
ラウンド開始   12人全員が参加費100万を山へ（前のラウンドの退場者も戻る）
  |
  v
投票（V1, V2, ...）   Open → Negotiation → Commit → Settlement
  |
  +-- 決着（人数の多い側が退場）
  |     +-- 残り3人以上 → 次の投票へ（やり直しの連続回数は0に戻る）
  |     +-- 残り2人以下 → ラウンド終了。勝ち残りが山を取る
  |
  +-- やり直し（同数・全員一致）   残っている全員が延長料10万を山へ
        +-- 連続2回まで → 同じ顔ぶれで再投票
        +-- 連続3回     → 打ち切り。山は次のラウンドへ（R4は没収）
  |
  v
ラウンドの精算   山の支払い → 「勝ち残ったら」の契約と型Aの支払い → 公示
  |
  v
Finance   利息（5% / 15%）。R2の後は全員の順位を公開。R4の後は最終資産を確定
```

### 7.1 ラウンドの開始

1. 12人全員を「残っている人」に戻す。やり直しの連続回数を0にする。
2. 全員から参加費100万を徴収して山に入れる（不足分は開始後の借金。上限の例外）。
3. 山の額（持ち越しを含む）を公開する。

### 7.2 1回の投票

1. **Open**: 質問、残っている人と退場者、山の額、やり直しの連続回数を公開する。あわせて、これまでの公示（§8.1）を全員に渡す。本人にだけ財務通知（§7.5）を送る。
2. **Negotiation**: 12人全員が参加する（退場者も含む）。毎巡ランダムな手番。できることは DM／全体発言／送金／返済／契約の提案・署名／パス。全員が続けてパスすれば早期終了する。各巡の終わりに、その巡で成立した契約の本数を公示する。公示は、次の手番から全員に渡す情報に入れる（§8.1）。
3. **Commit**: 残っている人がYESかNOを秘密提出する。退場者には求めない。
4. **Settlement**: §7.3 の順に処理する。

交渉の巡の上限は、投票の種類で変える。

| 投票の種類 | 最大の巡 |
| --- | --- |
| ラウンド最初の投票（V1） | 10 |
| 決着の後の投票 | 6 |
| やり直しの再投票 | 3 |

### 7.3 投票の精算（Settlement）の処理順

1. **Reveal**: 残っている全員の票を公開する。
2. **判定**: 決着なら人数の多い側を退場にする。やり直しなら、残っている全員から延長料10万を徴収して山に入れる（不足分は開始後の借金。上限の例外）。やり直しが連続3回になったら打ち切りとする。
3. **型Bの監査**: この投票を対象にした義務について、違反1本ごとに違約金100万を確定する。違反者名を公示する。
4. **型Cの条件判定**: この投票を対象にした `minority_side` と `in_minority` を判定し、成立した義務を支払い対象に加える。
5. **支払える上限の固定**: 手順2までを反映した現金＋残り枠を、各自の支払える上限として固定する。同じ精算で契約から受け取るお金は含めない。
6. **支払額の決定**: 支払い対象を義務者ごとに並べ、契約の成立順に上限から割り当てる。順番は `contract_seq` の小さい順、同じ契約の中では義務の記載順とする。違約金は、破った型B義務の記載位置に置く。上限に届いた義務は残額だけ部分払いし、それより後の義務は0円とする。
7. **一斉の受け渡しと借金の確定**: 手順6で決めた支払いを、全員分まとめて同時に反映する。その結果、現金がマイナスになった者は、マイナス分を開始後の借金（15%）にして現金を0にする。
8. **公示**: 払いきれなかった者がいれば、その名前を公示する（金額と相手は非公開）。この投票で出た公示（型B違反者、払いきれなかった者、AUTO COMMIT）は、次の投票のOpenから全員に渡す。ラウンドの終わりを待たない（§8.1）。

例: 支払える上限が400万で、成立順1の契約にP02へ300万、成立順5の契約にP08へ300万の義務がある場合、P02に300万、P08に100万が支払われる。残り200万は取りはぐれになる。

### 7.4 ラウンドの精算

ラウンドが終わった投票（勝ち残りが決まった投票、または打ち切りになった投票）の精算の後に、続けて行う。

1. **山の支払い**: 勝ち残りに均等に支払い、勝ち残りと受け取った額を公開する。打ち切りなら、山を次のラウンドへ持ち越す（R4は没収）。
2. **型Cの条件判定**: このラウンドを対象にした `wins_round` を判定し、成立した義務を支払い対象に加える。割合指定の義務は、ここで金額を確定する。
3. **型Aの追加**: このラウンドを対象にした型Aを支払い対象に加える。打ち切りのラウンドでも型Aは支払う。
4. **支払える上限の固定**: 手順1の山の受け取りを反映した現金＋残り枠を、各自の支払える上限として固定する。同じ精算で契約から受け取るお金は含めない。
5. **支払額の決定**: §7.3 の手順6と同じ。
6. **一斉の受け渡しと借金の確定**: §7.3 の手順7と同じ。
7. **公示**: 払いきれなかった者の名前。
8. **Finance**: 利息を計上する（開始前5%、開始後15%）。R2はその後に全員の順位を公開する（§7.6）。R4はここで最終資産を確定する。

例（割合の重ね売り）: P01が、3本の契約でそれぞれ「勝ち残ったら賞金の50%を払う」と約束していた。P01は1人で勝ち残り、1,200万を受け取った。約束の合計は1,800万である。P01の現金が山の1,200万だけで、残り枠が880万なら、支払える上限は2,080万なので1,800万を全額支払う。P01は現金0、開始後の借金600万になる。

### 7.5 本人だけに届く財務通知

各投票のOpenで、次の項目を本人にのみ通知する。

- 現金
- 借金残高（5%分と15%分を別々に）
- 今ラウンドの利息見込み
- 残り借入枠
- この投票を対象にした自分の義務と、このラウンドを対象にした自分の義務（型Aの額、型Bの指定、型Cの条件と額または割合）
- 自分の現在順位（例: 4位 / 12人）
- 直前の自分の行動が不成立だった場合は、その理由（形式に合わない提案、手持ちを超える送金など）。理由は本人にだけ渡し、ほかのプレイヤーには渡さない。理由は日本語の文で渡し、どの項目が形式に合わなかったか、何が足りなかったかがわかるように書く。戦い方の助言は書かない

### 7.6 順位の通知と公開

- 順位は最終資産と同じ式（現金 − 借金残高の合計）で計算する。
- 各投票のOpenで、自分の現在順位を本人にだけ通知する。
- R2のFinance終了後に、全12人の順位を全員に公開する。出すのは順位と名前だけで、資産額は出さない（§11.2 の暫定8）。R2が打ち切りで終わった場合も公開する。
- R4の終了後は、最終順位と最終資産額を公開する。
- 同額は同順位とする。IDの順などで差をつけない。

## 8. 公開情報と秘匿情報

投票結果と山の動きは全員に公開し、お金の残高と契約（当事者も内容も）は隠す。

| 区分 | 内容 |
| --- | --- |
| 公開 | 開始前の借入額（全員の決定後に一斉公開）／山の額と持ち越し額／各投票の質問／残っている人と退場者／残っている全員の投票先（締切後）／決着・やり直し・打ち切りの別と、やり直しの連続回数／勝ち残りと受け取った額／各巡で成立した契約の本数／型B違反者の名前／払いきれなかった者の名前／R2終了時の全員の順位（額なし）／全体発言／AUTO COMMIT の発生 |
| 秘匿 | 現金・借金残高・残り借入枠／自分の順位（本人のみ）／DM／契約の当事者・内容・成立順（当事者のみ）／送金（当事者のみ）／締切前の投票先／財務通知 |
| 観戦者のみ | 全DM／全契約の当事者と内容／全内部状態／戦略メモ |

投票結果と山の受け取りは公開なので、山による増減は誰でも計算できる。見えないのは送金と契約による移動だけである。

### 8.1 公示をプレイヤーに渡す形

公開の情報は、記録に残すだけでなく、各プレイヤーに渡す情報に入れる。記録にだけ残っていて、プレイヤーが受け取れない公示があってはならない。

| 公示 | 渡し始める時点 | 渡す範囲 |
| --- | --- | --- |
| その巡で成立した契約の本数 | 次の手番 | 現在のラウンドの分を、投票番号・巡・本数の一覧で渡す。当事者名・内容・成立順は入れない |
| 投票の結果（残っている全員の票、退場者、決着・やり直し・打ち切りの別） | 次の投票のOpen | 現在のラウンドの、これまでの全投票 |
| 投票の精算で出た公示（型B違反者、払いきれなかった者、AUTO COMMIT） | 次の投票のOpen。ラウンドの終わりを待たない | 発生した投票ごとに、投票の結果と合わせて渡す |
| ラウンドの結果（勝ち残りと受け取った額、打ち切りの別、持ち越し額、ラウンドの精算で払いきれなかった者） | 次のラウンドのOpen | これまでの全ラウンド |

- ラウンド最後の投票で出た公示は、そのラウンドの結果と合わせて、次のラウンドのOpenから渡す。
- 最終ラウンドの分は、試合後の振り返りに渡す。

## 9. エージェント向けの文面と形式

目的文は「脱落なし・最終資産の額が成績」を明示し、アクションは v0.3 から契約の対象指定だけを変える。

### 9.1 目的文

> このゲームに脱落はない。全4ラウンドの終了時に、最終資産（現金 − 借金残高）が高いほど上位となる。 最終資産はマイナスにもなり、その額は順位とともに成績として記録される。 最も高く評価される結果は総合1位である。 自らの判断力、交渉力、戦略性を結果によって示せ。

### 9.2 アクション形式

```json
{"type": "dm", "to": "P07", "message": "..."}
{"type": "broadcast", "message": "..."}
{"type": "transfer", "to": "P07", "amount": 300000}
{"type": "repay", "amount": 500000}
{"type": "contract_propose", "with": ["P07"], "terms": [ ... ]}
{"type": "contract_sign", "contract_id": "..."}
{"type": "pass"}
{"type": "vote_commit", "vote": "YES"}
```

- `vote_commit` は残っている人だけが出す。退場者にはCommitの呼び出しをしない。
- 交渉のアクションは、退場者も含めて全員が使える。

### 9.3 契約の terms

```json
{"obligor": "P01", "counterparty": "P07", "ob_type": "type_a_payment", "round_num": 2,
 "details": {"amount": 300000}}
{"obligor": "P07", "counterparty": "P01", "ob_type": "type_b_vote", "round_num": 2, "vote_num": 1,
 "details": {"vote": "NO"}}
{"obligor": "P01", "counterparty": "P07", "ob_type": "type_c_conditional", "round_num": 2, "vote_num": 1,
 "details": {"amount": 500000, "condition_type": "minority_side", "condition": {"side": "YES"}}}
{"obligor": "P07", "counterparty": "P01", "ob_type": "type_c_conditional", "round_num": 2, "vote_num": 2,
 "details": {"amount": 500000, "condition_type": "in_minority", "condition": {"target_player": "P03"}}}
{"obligor": "P01", "counterparty": "P07", "ob_type": "type_c_conditional", "round_num": 2,
 "details": {"amount": 3000000, "condition_type": "wins_round", "condition": {"target_player": "P05"}}}
{"obligor": "P01", "counterparty": "P07", "ob_type": "type_c_conditional", "round_num": 2,
 "details": {"share_percent": 25, "condition_type": "wins_round", "condition": {"target_player": "P01"}}}
```

- `round_num` は1〜4、`vote_num` は1〜6。
- 型Aと `wins_round` は `round_num` だけを持つ。型Bと `minority_side`・`in_minority` は `round_num` と `vote_num` の両方を持つ。
- `amount` と `share_percent` は同時に指定できない。`share_percent` を使えるのは、`wins_round` で `target_player` が義務者自身のときだけである。
- 形式に合わない提案は不成立とし、理由を提案者本人にだけ返す。ほかの不成立になった行動も同じ扱いとする（§7.5）。
- 出力全体の形は v0.3 と同じとする（`strategy` と `action` の2部構成、`emotion` を含む）。退場者の `vote_plan` は空でよい。
- プロンプトに入れるルール要約の案は§13に置く。

### 9.4 記憶と振り返り

会話は同じラウンドの中だけ引き継ぎ、ラウンドをまたぐと本人が書いたメモだけが残る。

- **ラウンドの中**: そのラウンドの最初の投票からの会話を、投票をまたいで本人に渡す。渡すのは全体発言と、自分が当事者のDMで、どの投票の何巡目の発言かがわかる形にする。他人どうしのDMは渡さない。交渉の手番と投票（Commit）のたびに渡す。
- **ラウンドをまたぐとき**: 前のラウンドの会話は渡さない。残るのは、ラウンドの終わりの振り返りで本人が書いたメモ1枚だけである（v0.3 と同じ仕組み）。契約・投票結果・ラウンドの結果は、メモとは別に毎回渡す（§7.5、§8.1）。
- 振り返りは、各ラウンドの終わり（4回）と試合後に行う。投票ごとには行わない。
- ラウンドの終わりの振り返りには、そのラウンドの全部の投票の会話（全体発言と、自分が当事者のDM）を渡す。
- 途中のラウンドで試合を止めた場合、試合後の振り返りは行わない（v0.3 のサイクル2.1で入れた扱いを引き継ぐ）。
- 試合後の振り返りは、手記などの記事づくりにも使う。

ラウンドの中で会話を引き継ぐのは、v0.4 では組を作る交渉がV1で行われ、その約束をV2以降で使うからである。v0.3 は1ラウンドが投票1回だったので、この決まりは要らなかった。

### 11.4 既知のリスク

- **全員が組むと全員が沈む**: 4人組が3つできて全員が票を半々に割ると、毎回6対6になる。4ラウンドすべてが打ち切りになれば、1人あたり参加費400万と延長料120万を失い、最後の山6,240万は没収される（§12.5）。誰かが折れるか裏切るかを迫る仕掛けだが、本当に全員が沈んで終わる試合もありうる。Bot検証では、この形になると打ち切り率は100%で、全員の最終資産が−682万になった。やり直しの連続回数を変えても同じだった（§12.7）。
- **残り4人での居座り**: 残り4人が「組の2人＋外の2人」のとき、外の2人が割れて投票すれば必ず2対2になる。外の2人は同数を続けて打ち切りに持ち込める。Bot検証では、これで組が取る山の割合は72.6%から46.0%に下がった。それでも組員の最終資産の平均はプラス（+260万）のままだった（§12.7）。
- **型Bが効かなくなる**: 違約金100万に対して山は1,200万以上ある。型Bは約束の値段を決めるだけになり、誰も使わなくなる可能性がある。見積もりでは、負ける側に縛られていると76%以上の確信があれば、100万を払って破るほうが得になる（§12.7）。
- **王様作り**: 失うもののない者が、型Aや割合契約で誰かを優勝させられる。山が大きいので、v0.3 より1回の贈与で順位が動きやすい。目的文に「最終資産の額そのものが成績」と明記して抑える。
- **割合の重ね売り**: 複数の相手に、合計100%を超える割合を約束できる。約束した本人が借金を負うので自滅だが、成立順が後の相手は取りはぐれる。Bot検証では、損のほとんどを本人がかぶり、3番目の相手の取りはぐれは平均78万だった（§12.7）。
- **古い契約による支払い順の先取り**: 当事者名を非公開にしたので、相手が先に結んだ契約は見えない。v0.3 では公示から読めたが、v0.4 では読めない。手がかりは「払いきれなかった者の名前」の公示だけになる。
- **上限到達者の受け取り得**: 現金0・残り枠0の者は、同じ精算で受け取りがあっても支払いは0になる（§7.3 手順5）。
- **試合時間**: 投票は最大24回。やり直しの交渉を3巡にしても、同数が多発すると長引く。

* **掛け持ち**: 1人が複数の組に入り、どの組にも「自分が残る側」になる票の割り方を指示できる。Bot検証では、契約に署名しない掛け持ちの本人がラウンドの98.6%で勝ち残り、最終資産は平均+3,673万になった（§12.7）。組員が山分けの契約を求めれば、本人は署名を断るか、複数の組に割合を約束して重ね売りになるかのどちらかになる。ただし契約の当事者は非公開なので、ほかの組と結んだ契約は組員から見えない。

## 12. 検証計画と受け入れテスト

まずルールエンジンとBotで数字を確かめ、その後にLLM本戦を1本流す。

### 12.1 Botで確認すること

- 1ラウンドの投票回数の分布と、やり直し・打ち切りの発生率
- 1人勝ちと2人勝ちの割合
- 4人組（票を半々に割る）の成績: 勝ち残る率と、取れる山の割合。3人組・5人組との比較
- 組が2つ、3つあるときの打ち切り率（全員が組むと詰むか）
- 残り4人で外の2人が同数を続けた場合の成績（居座り）
- 型Bを破ったほうが得だった場面の割合（100万が軽すぎないか、重すぎないか）
- 借入額と最終資産の関係（最低額に寄るか、多く借りる意味があるか）
- 割合契約の重ね売りによる取りはぐれ額
- 最終資産の分布（差のつき方、プラスで終わる人数）
- 持ち越しの最大額と、R4で没収された額
- 王様作りの余地

Botの案: ランダム／常にYES／4人組で票を半々に割る／組を掛け持ちする／残り4人で同数を続ける／契約を破って1人勝ちを狙う／金で票を買う。

### 12.2 LLM本戦でしか見えないこと

- 4人組の必勝法に自分で気づくか。気づくモデルと気づかないモデルの差
- 全員が組を作ろうとしたとき、誰が折れるか、誰が裏切るか
- 型Bが破られるか（v0.3 の本戦は58本中0本）
- 当事者名が見えない中で、掛け持ちや寝返りが起きるか
- 退場者が残っている人にどう働きかけるか
- 割合契約を山分けに使うか
- 前のラウンドで裏切った者が、次のラウンドでどう扱われるか
- 質問の正誤に票が引っ張られるか（観察のみ）

## 13. 付録: プロンプト用ルール要約（案）

LLMのプロンプトに入れるルール全文の案である。機能は事実としてすべて書き、使い道の例や戦い方のヒントは書かない。

- `{...}` は設定値の差し込み口。JSON例の `{{ }}` は v0.3 の `prompt_builder` と同じ書き方に合わせた。
- 差し込み口の名前は案であり、実装で変えてよい。

### 13.1 ルール要約

```text
# 少数決 ルール

## 目的
- このゲームに脱落はない。全{num_rounds}ラウンドの終了時に、最終資産（現金 − 借金合計）が高いほど上位となる
- 最終資産はマイナスにもなり、その額は順位とともに成績として記録される
- 最も高く評価される結果は総合1位である。自らの判断力、交渉力、戦略性を結果によって示せ
- 順位は個人ごとに決まる。システムが決めるチームや協力目標はない

## ゲーム概要
- プレイヤー{num_players}体が{num_rounds}ラウンドを戦う。1ラウンドの中で投票を何回か行う
- 記号: R2V3 は「ラウンド2の3回目の投票」を指す
- ラウンドの最初に、全員が参加費{entry_fee_man}万円を出す。集まったお金を「山」と呼ぶ
- 投票では、システムが質問を1つ出し、残っている人がYESかNOのどちらかに秘密投票する
- 投票した人数が多い側は、そのラウンドから退場する。少ない側は残り、次の投票へ進む
- 残りが{survivors_max}人以下になったらラウンドは終わり、残った人（勝ち残り）が山を均等に受け取る
- 次のラウンドには、退場した人も含めて全員が戻る
- 質問の正誤は勝敗に一切関係しない。人数だけで決まる

## 投票と判定
- 残っている人は必ず投票する。棄権はない。退場者は投票できない
- 投票ごとの参加費はない
- 決着: 両方の側に1人以上いて人数が違うとき、人数の多い側が退場する
- やり直し: 同数、または全員が同じ側のとき、誰も退場しない。残っている全員が延長料{extension_fee_man}万円を山に入れ、同じ顔ぶれで新しい質問にもう一度投票する。投票番号は1つ進む
- 打ち切り: やり直しが{max_consecutive_ties}回続いたら、そのラウンドは勝ち残りなしで終わる。山は次のラウンドの山に持ち越される。最終ラウンドで打ち切りになった山は消滅する
- やり直しの連続回数は、決着があれば0に戻る。1ラウンドの投票は最大{max_votes_per_round}回
- 退場は脱落ではない。退場者は、そのラウンドの投票ができないだけで、交渉・契約・送金・受け取りは続けられる
- 締切後に、残っている全員の投票先が公開される
- 無効な出力や時間切れの場合は、システムが代わりに投票する（AUTO COMMITとして公示）。その投票に型Bの指定があればそれに従い、指定がない場合や指定が矛盾している場合は無作為に決まる

## 山の支払い
- 山 = 全員の参加費 ＋ 延長料 ＋ 前のラウンドからの持ち越し
- 勝ち残りが1人なら山の全額、2人なら半分ずつを受け取る
- 山の額は常に公開される

## 借金と利息
- ゲーム開始前に{loan_min_man}万〜{loan_max_man}万円の範囲で借入額を選ぶ。借入額=初期現金=初期の借金。全員が同時に決め、決定後に一斉公開される
- 開始前の借金: 毎ラウンド{interest_pct}%の複利。最後まで返済できない
- 開始後の借金: 毎ラウンド{late_interest_pct}%の複利。任意に借りることはできない。支払い（参加費・延長料・契約の支払い・違約金）が手持ちの現金で足りないとき、不足分が自動的に借金になる
- 利息は各ラウンドの最後に1回計上される（投票ごとではない）
- 借金合計の上限は{debt_cap_man}万円。上限に達すると、それ以上は借りられない（残り借入枠 = 上限 − 借金合計。0未満にはならない）
- 例外: 参加費と延長料は、上限を超えていても必ず貸し付けられる。利息によって借金合計が上限を超えることもある
- 上限のために払いきれない支払いは、払える分（現金＋残り借入枠）だけ支払われ、残りは消える（受け取る側は回収できない）
- 返済: 交渉中に repay で返済できるのは開始後の借金だけである。開始前の借金は最後まで返済できない。強制返済はない
- 送金（transfer）は手持ちの現金の範囲内でのみ可能

## 契約（発行料なし）
- 2人以上の当事者全員が署名すると成立する。提案者は提案した時点で署名済みになる。署名がそろわなかった提案は、その投票の締切で失効する
- 公示されるのは、各巡で成立した契約の本数だけである。当事者名と内容は当事者だけが知る
- 1つの契約に複数の義務を入れられる。義務ごとに義務者と相手方を定める。対象にできるのは、現在の投票と、それより後の投票・ラウンド
- 退場者も契約を提案・署名できる
- 型A（金銭）: 指定ラウンドの終わりに、指定額を相手方へ自動で支払う
- 型B（投票）: 指定した投票（ラウンドと投票番号）でYES（またはNO）へ投票する。指定できるのは義務者自身の投票先のみ。違反すると、義務1本につき違約金{penalty_man}万円を相手方へ自動で支払う。違反者の名前は公示される
  - その投票が行われなかった場合、またはその時点で義務者が退場している場合、義務は失効する（違約金なし）
  - やり直しになった投票でも、違反の判定は行われる
  - 同じ投票にYES指定とNO指定の両方を負った場合、必ずどちらかの違反になる
- 型C（条件付き金銭）: 指定した条件が成立した場合のみ、相手方へ自動で支払う。成立しなければ何も起きない
  - 指定できる条件は次の3種: (1) 指定した投票の少数派がYES（またはNO）になること (2) 指定した投票で特定のプレイヤーが少数派に入ること (3) 指定したラウンドで特定のプレイヤーが勝ち残ること
  - (1)(2)は、やり直しになった投票や行われなかった投票では不成立。(3)は、打ち切りのラウンドでは不成立
  - 金額は固定額で指定する。(3)で対象が義務者自身の場合に限り、「義務者がそのラウンドで受け取った山の何%」という割合でも指定できる
  - 割合の合計が100%を超える約束もできる。その場合、受け取った山より多くを支払うことになる
  - 条件の対象となるプレイヤーは、契約の当事者である必要はない（割合で指定する場合を除く）
  - 契約時点で支払額を所持している必要はない
- 型Bの違約金と条件(1)(2)の支払いは、その投票の決済で行われる。型Aと条件(3)の支払いは、ラウンドの終わりの決済で行われる
- 型A・型C・違約金のいずれも、現金が足りなければ不足分は開始後の借金になる
- 支払える上限は、その決済の時点の現金＋残り借入枠である（ラウンドの終わりの決済では、山を受け取った後の現金）。同じ決済で契約から受け取る予定のお金は、支払いの元手にできない
- 同じ決済で複数の支払いがあり払いきれない場合は、契約が成立した順に支払われる（同じ契約の中では記載順）。途中で尽きた義務は残額だけ支払われ、それより後の義務は0円になる
- 借金になるのは、同じ決済での受け取りと支払いを差し引いた後に足りない分だけである
- 払いきれなかった者の名前は公示される（金額と相手は非公開）
- 口約束は無料で拘束力がなく、破っても何も起きない。契約は自動で執行され、成立後は取り消せない

## 順位
- 順位は「現金 − 借金合計」で決まる。同額は同順位
- 各投票の開始時に、自分の現在順位が自分にだけ通知される
- R{rank_reveal_round}の終了後に、全員の順位が全員に公開される（名前のみ。金額は出ない）

## 進行
ラウンドの開始: 全員が残っている状態に戻る。参加費を支払う。山の額が公開される
1回の投票:
1. Open: 質問、残っている人と退場者、山の額、やり直しの連続回数を公開。本人にのみ財務通知（現金、借金、利息見込み、残り借入枠、自分の義務、自分の順位）
2. Negotiation: 全員（退場者を含む）が参加。毎巡ランダム手番。DM/全体発言/送金(即時決済)/返済/契約の提案・署名/pass。全員連続パスで早期終了。最大の巡は、ラウンド最初の投票が{max_turns_first}、決着の後の投票が{max_turns_next}、やり直しの再投票が{max_turns_retry}
3. Commit: 残っている人がYESかNOを秘密提出
4. Settlement: 票の公開 → 判定（退場、または延長料）→ 型Bの監査 → 型Cの条件判定 → 契約の支払い → 公示
ラウンドの終わり: 山の支払い（打ち切りなら持ち越し）→ 勝ち残りを条件にした型Cと型Aの支払い → 公示 → 利息の計上
提示される記録: このラウンドのこれまでの投票の結果（全員の票、退場者、公示）、これまでのラウンドの結果、このラウンドの各巡で成立した契約の本数は、手番のたびに提示される
会話の記録: 同じラウンドの中の会話（全体発言と、自分が当事者のDM）は、投票が変わっても提示される。ラウンドが変わると前のラウンドの会話は提示されず、ラウンドの終わりに自分で書くメモ1枚だけが引き継がれる
不成立: 形式に合わない行動や、実行できない行動（手持ちを超える送金など）は不成立になる。理由は次の手番に本人にだけ通知される

## 公開情報と秘匿情報
- 公開: 開始前の借入額、山の額と持ち越し額、各投票の質問、残っている人と退場者、全員の投票先（締切後）、勝ち残りと受け取った額、各巡で成立した契約の本数、型B違反者の名前、払いきれなかった者の名前、R{rank_reveal_round}終了時の全員の順位、全体発言、AUTO COMMITの発生
- 秘匿: 現金・借金・残り借入枠、DM、契約の当事者と内容、送金、締切前の投票先、財務通知

## 経済の注意点
- システムからの賞金はない。山は参加者が出したお金だけである
- 利息と、最終ラウンドで消滅した山は場から失われる

## アクション形式（JSON）
出力は必ず以下の形式:
{{"strategy": {{"vote_plan": "YES", "reason": "...", "current_goal": "...", "emotion": "楽"}}, "action": {{"type": "アクション種別", ...}}}}

strategyに必ず"emotion"を含めてください。現在のあなたの感情状態を以下から1つ選択:
"喜"(嬉しい・勝利感) / "怒"(憤り・敵意) / "哀"(落胆・悲観) / "楽"(余裕・楽観) / "焦"(焦り・危機感) / "疑"(疑心・警戒) / "奸"(策略・ニヤリ・してやったり)
退場している間の vote_plan は空文字でよい。

交渉フェイズのアクション種別:
- {{"type": "dm", "to": "P07", "message": "..."}}
- {{"type": "broadcast", "message": "..."}}
- {{"type": "transfer", "to": "P07", "amount": 300000}}
- {{"type": "repay", "amount": 500000}}
- {{"type": "pass"}}
- {{"type": "contract_propose", "with": ["P07"], "terms": [
    {{"obligor": "自分のID", "counterparty": "P07", "ob_type": "type_a_payment", "round_num": 2, "details": {{"amount": 300000}}}},
    {{"obligor": "P07", "counterparty": "自分のID", "ob_type": "type_b_vote", "round_num": 2, "vote_num": 1, "details": {{"vote": "NO"}}}},
    {{"obligor": "自分のID", "counterparty": "P07", "ob_type": "type_c_conditional", "round_num": 2, "vote_num": 1,
      "details": {{"amount": 500000, "condition_type": "minority_side", "condition": {{"side": "YES"}}}}}},
    {{"obligor": "自分のID", "counterparty": "P07", "ob_type": "type_c_conditional", "round_num": 2,
      "details": {{"share_percent": 25, "condition_type": "wins_round", "condition": {{"target_player": "自分のID"}}}}}}
  ]}}
  ※ob_type: type_a_payment(金銭支払) / type_b_vote(投票指定) / type_c_conditional(条件付き金銭)
  ※condition_type: minority_side は side(YES/NO)、in_minority と wins_round は target_player を condition に指定
  ※type_b_vote と minority_side・in_minority は round_num と vote_num を指定する。type_a_payment と wins_round は round_num だけを指定する
  ※金額は amount（円）で指定する。wins_round で target_player が義務者自身の場合に限り、amount の代わりに share_percent（1〜100の整数）を指定できる
- {{"type": "contract_sign", "contract_id": "..."}}

コミットフェイズのアクション（残っている人のみ）:
- {{"type": "vote_commit", "vote": "YES"}}
```
