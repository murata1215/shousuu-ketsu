# Bot検証レポート（18人・サイクル7.0）

本レポートは第2戦（18体ロスター）の準備（サイクル7.0）として、少数決のルールエンジンを
Bot（LLM不使用、費用0円）で18人設定（`sim/scenarios.py::"V1_18p"`、V1の18人版。構成は
V1と同じ「18人とも無作為」）で1,000試合回し、既存の12人版V1（`data/sim_v0_4/V1_seed1_n1000.json`、
サイクル4.1作成）と比較したものである。ルール（v0.5）の数字は一切変えていない。

唯一の挙動変更は、けいすけさんの決定6（本サイクル）で追加した
「1ラウンドの投票がmax_votes_per_round（6回）に達しても決着しなければ、やり直し連続3回の
打ち切りと同じ扱いでそのラウンドを流す」ルールである（12人設定では構造上発生しない状態の
ため、これまでは`AssertionError`で試合を止めていた。`engine/game.py::_run_round`）。

## 指示書の項目ごとの所見

### 4ラウンドで勝ち抜きが決着するか（決着しない割合）

ラウンド単位の打ち切り率は12人5.83%→18人3.28%と、**18人のほうが決着しやすい**。
試合単位（4ラウンドすべてが打ち切りゼロで終わる割合）も78.4%→87.7%と同じ方向。
人数が増えるほど「同数（n対n）」になる組み合わせの相対頻度が減るため、やり直し
（したがって打ち切り）が起きにくくなるという無作為投票の構造上自然な結果である。

### 同数打ち切り・持ち越しの起きる割合

打ち切り自体は上記のとおり減るが、持ち越し額の最大は31,200,000円→43,800,000円、
R4没収の平均額（没収時のみ）は14,216,949円→21,883,333円と、**起きたときの金額は
人数（参加費の総額＝18人×100万円）に比例して大きくなる**。

### 「6回で流れた」割合（けいすけさん決定6の新ルール）

4,000ラウンド中10ラウンド（0.25%）、1,000試合中10試合（1.0%）で実際に発生した。
12人設定では0件（想定どおり構造上起きない）。頻度は低いが、1,000試合という規模では
確実に起こる現象であり、新ルールを足さなければこの10試合は`AssertionError`で停止していた
ことになる。

### 最終資産の分布、プラスで終わる人数

18人のほうが最大値・標準偏差ともに大きく（57.2M vs 39.1M、σ7.9M vs σ6.5M）、
山の規模が大きくなる分だけ勝者の取り分の振れ幅も広がる。プラスで終わる人数の平均は
18人中4.86人（27.0%）、12人中4.47人（37.3%）で、**比率としては18人のほうがやや低い**
（参加費負担・利息の仕組みは変えていないため、母数が増えた分だけ「取れない側」も
増える自然な結果）。

## 注記・申し送り

- ルール・設定値は一切変更していない（`max_votes_per_round=6`・`max_consecutive_ties=3`・
  `survivors_max=2`・参加費100万円等はV1・V1_18pで共通。`tests/test_simulate.py::
  test_v1_18p_config_has_18_players_and_unchanged_other_settings`で固定）。
- `sim/scenarios.py`の既存V2〜V11（組・居座り・掛け持ち等のシナリオ）は18人化していない
  （本サイクルの対象範囲外。V2〜V11のグループ構造は12人固定のまま一切変更していない）。
- `sim/metrics.py::type_b_break_value_estimate`等の型B関連の見積もり関数は12人の
  split_counts（7対5等）を前提にしており、18人には未対応（本サイクルでは呼んでいない
  ため実害はない。18人で型B検証をする場合は別サイクルで対応が必要）。
- `scripts/report_bot_simulation_v0_4.py`（全25条件の正式レポート生成）は変更していない
  （"V1_18p"を含めていない。12人の報告書の数字は1件も変わらない）。
